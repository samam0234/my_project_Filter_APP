# 운영 콘솔 (프론트엔드 2)

## 개요

운영 콘솔은 저장소 `console/`의 별도 React 앱이다. 사용자 앱과 저장소, 포트, 배포 단위가 다르다.
기술은 사용자 앱과 같이 TypeScript, Vite 7, Tailwind, Zustand다. 로컬 주소는 `http://localhost:5174`다.

하는 일은 서비스를 쓰는 것이 아니라 서비스를 보는 것이다.
전체 작업, 전체 배치, 학습 후보 검수, 회원 잠금과 삭제, 디스크와 설정 점검이다.

Docker Compose에는 콘솔 서비스가 없다. 공개 서버에도 콘솔 화면을 올리지 않았다.
관리자 PC에서 콘솔을 띄우고, 그 화면이 서버의 `/api/v1/console/*`를 호출한다.

## 엔진

사용자 앱과 같은 계열이다. 차이를 일부러 두지 않아 화면 규칙과 빌드 방식을 다시 배우지 않게 했다.

| 항목 | 내용 |
|------|------|
| 실행 | `cd console` 후 `npm install`, `npm run dev` |
| 백엔드 | 8000이 떠 있어야 표가 채워진다 |
| 갱신 | 30초와 수동 새로고침 |
| 테스트 | Vitest. 인수인계 기준 21개 통과. 학습 화면이 중심 |

접근은 네 가지다.

| 조건 | 결과 |
|------|------|
| `CONSOLE_ADMINS`에 있는 아이디로 로그인 | 어디서든 사용 |
| 서버 PC이고 `CONSOLE_REQUIRE_LOGIN=false` | 로그인 없이 사용. 헤더에 서버 PC라고 표시 |
| 관리자가 아닌 회원 | 세션을 바로 끊고 거절 |
| 로그인 없이 원격 | 로그인 화면 |

운영은 `CONSOLE_REQUIRE_LOGIN=true`다.
관리자 아이디는 가입을 먼저 하고 나중에 `.env`에 적는다. 없는 아이디를 미리 적어 두면, 그 아이디를 먼저 가입한 사람이 관리자가 된다.
관리자 계정은 사용자 앱에서 스스로 탈퇴할 수 없다. 콘솔에 들어갈 사람이 사라지는 상황을 막기 위해서다.
검수자 이름은 `admin:{아이디}`로 남는다. 서버 PC에서 로그인 없이 본 경우는 `console:local`이다.

로컬에서는 5173과 5174가 쿠키를 공유한다. 쿠키는 포트를 구분하지 않는다.

## 화면

| 메뉴 | API | 내용 |
|------|-----|------|
| 로그인 | `GET /api/v1/console/me` | 관리자 확인 |
| 대시보드 | `/health`, `/console/jobs` | 상태, 집계, 최근 작업 |
| 작업 목록 | `/console/jobs`, `/console/files/{id}/*` | 사진, 영상, GIF. 소유자와 관계없이 전체 |
| 배치 현황 | `GET /console/batches` | 진행률과 실패 수. 회원 사진은 보여 주지 않음 |
| 학습 데이터 | `/console/learning/*` | 승인, 정답 수정 후 승인, 거절, 일괄, 삭제 |
| 회원 관리 | `/console/users*` | 검색, 잠금 해제, 세션 끊기, 삭제 |
| 시스템 | `/console/system`, `POST .../cleanup` | 설정, 런타임, 용량, 정리 |
| 바로가기 | 없음 | 사용자 앱, Swagger, health |

사용자 앱의 `GET /api/v1/jobs`는 본인 작업만 돌려준다. 콘솔은 그 API를 쓰지 않는다.

## 검수가 막는 것

승인된 문장만 RAG 예시와 LoRA 학습에 들어간다.
사용자가 틀린 정답을 알려 주면, 그 문장과 비슷한 다른 사람의 요청까지 잘못 해석될 수 있다. 콘솔 승인이 그 관문이다.

| 출처 | 들어오는 곳 | 검수 |
|------|-------------|------|
| correction | 결과 화면의 정답 알려주기 | 문장과 정답이 맞는지 |
| like | 좋아요 | 대체로 그대로 승인 |
| request | 회원 업로드 문장과 그때의 해석 | 틀리면 정답을 고쳐 승인 |
| pipeline_failure | 세그 실패 사진 | YOLO 재학습 후보 |
| pseudo_label | 의사 라벨 스크립트 | 필요할 때만 |

같은 문장의 회원 요청은 후보를 한 건만 만든다.
승인하면 id 해시로 train과 val이 고정된다. val은 약 10%다. 다시 학습해도 같은 표본은 같은 쪽에 남는다.
삭제하면 사이드카 파일까지 지우고, 행은 비운 `deleted`로 남겨 다음 기동 때 되살아나지 않게 한다.
승인이나 삭제는 약 30초 안에 RAG 색인에 반영된다.

회원 삭제는 되돌리지 못한다. 아이디를 다시 입력해야 실행된다.
계정, 세션, 작업, 배치, 결과 파일, 실패 사진은 지운다.
학습 문장은 남기고 회원 연결만 끊는다. 비밀번호는 해시만 있어 콘솔에서도 볼 수 없다.

## 스크린샷

콘솔은 2026-10-08 사용자 앱 디자인 작업의 범위 밖이었다. 다크 운영 화면을 유지한다.
확인 장면은 로컬 `logs/ui_check/`의 학습 데이터, 배치, 회원, 시스템, 로그인이다.
포트폴리오 사이트는 그 장면 중 설명에 필요한 것만 다시 담는다. 회원 개인 정보가 보이는 캡처는 넣지 않는다.

시스템 화면은 모델을 미리 올리지 않는다. 첫 요청 전이면 세그 런타임이 "로드 전"이다.
배치 큐는 `BATCH_USE_CELERY=true`일 때만 Redis를 확인한다. 연결이 없으면 API 프로세스가 배치를 처리한다.

## 문제와 개선

이미 있는 것:

- 관리자 로그인과 서버 PC 예외
- 학습 관문, 회원 잠금, 세션 폐기, 계정 삭제
- 보관 기간이 지난 파일의 미리 보기와 즉시 정리
- 실패 사진 30일 정리. 계정 삭제 시 즉시 삭제

아직인 것:

- 콘솔을 공개 주소에 올리는 일. 올리려면 Cloudflare Access 같은 접근 제한이 먼저다.
- 2026-10-08 수준의 타이포와 간격 정리. 사용자 앱만 했다.
- 리버스 프록시 뒤에서 모든 요청이 127.0.0.1로 보이면, 로그인 설정이 느슨할 때 콘솔이 열릴 수 있다. 운영 preflight가 이 경우를 경고한다.
- `CONSOLE_ALLOW_REMOTE=true`는 로그인 없이 여는 예전 방법이다. 앞단 인증이 없으면 쓰지 않는다.

예정:

- 공개가 필요해지면 접근 제한을 먼저 둔 뒤 화면을 올린다.
- 스키마가 자주 바뀌면 콘솔의 검수 표와 함께 Alembic 이전을 맞춘다.
- 재학습 버튼은 아직 콘솔에 없다. 승인 수가 기준에 닿으면 스크립트 `scripts/retrain_lora.py`를 돌린다. 화면의 `재학습 N/200`은 그 기준을 보여 주는 숫자다.

## 이후 방향

콘솔은 관리자 수가 아주 적은 도구로 둔다.
사용자 앱처럼 누구나 여는 서비스로 만들지 않는다.
검수 기록과 삭제 기록은 서버 로그에 관리자 이름과 함께 남기는 현재 방식을 유지한다.
학습 품질은 모델 크기보다 이 화면에서 거른 문장에 더 좌우된다.
