# AI 서비스

여기서 말하는 AI 서비스는 두 층이다.

1. 컷앤킵 제품 안의 추론. FastAPI가 YOLO와 Ollama와 학습 루프를 호출한다.
2. 이 포트폴리오 폴더의 Flask 안내. 제품을 설명만 한다. 사진을 처리하지 않고, 제품 데이터베이스에 연결하지 않는다.

이 장은 1을 설명하고, 2가 무엇을 하지 않는지 경계를 적는다.

## 제품 추론의 개요

한 요청은 네 단계다.

1. 문장을 `ParsedPrompt`로 바꾼다. 대상, 효과, 강도, 크롭, 선택자.
2. YOLO26m-seg로 인스턴스 마스크를 만든다. 건물이나 하늘처럼 덩어리 배경은 SegFormer가 맡는다.
3. 선택자 규칙으로 그 중 몇 개를 고른다.
4. 효과를 적용한다. 남기기, 블러, 크롭, 지우기.

기본 해석 모델은 로컬 Ollama `gemma4:e4b`다. 키와 호출 비용이 없고, 문장은 운영자 PC에서 처리된다.
사용자는 작업실에서 `gemma4:12b`와 `qwen3.8:27b`를 고를 수 있다. 설치되어 있을 때만 활성이다.

이 PC(RTX 4070 SUPER 12GB)에서 같은 문장의 대략적인 해석 시간은 다음과 같다.

| 모델 | 특징 |
|------|------|
| e4b | 기본. 첫 호출 약 10초, 이후 약 1초 |
| 12b | 이후에도 약 29초. 모델 교체 직후는 더 김 |
| 27b | 12GB에 다 올라가지 않아 일부가 CPU. 첫 호출 약 3분 |

12b나 27b가 e4b보다 이 과제에서 더 정확하다는 평가는 하지 않았다.
해석 제한 시간은 기본 30초, 12b 90초, 27b 180초다.

## 엔진

| 역할 | 구현 |
|------|------|
| 비전 서빙 | `backend/models/yolo26m-seg.pt` 또는 `.onnx` |
| 배경 덩어리 | SegFormer ADE20K ONNX. 건물, 하늘, 도로 등 14종 |
| 학습형 지우기 | LaMa ONNX. 없으면 Telea. 없으면 기동 중 받는 옵션이 있다 |
| 열린 어휘 | Grounding DINO와 SAM2. `OPEN_VOCAB_ENABLED` 기본 false |
| 문장 | `prompt_llm.py`. provider는 ollama, lora, openai, gemini, heuristic |
| 규격 | `prompt_spec.py`. 서빙 지시문과 LoRA 학습 정답이 같은 파일 |
| 폴백 | `LLM_FALLBACK`. 운영은 heuristic. 로컬 개발 기본은 다른 설정을 탈 수 있다 |
| 체인 | `PROMPT_CHAIN=langchain` |
| 검색 예시 | `prompt_rag.py` |
| 어댑터 | Qwen2.5-1.5B LoRA. `training/lora` |
| 흐름 | LangGraph 1.2 |

detect 전용 `.pt`를 세그 경로에 두지 않는다. 마스크가 없는 가중치다.
학습 스크립트의 출발 가중치는 여전히 `yolo26s-seg.pt`일 수 있다. 서빙 기본이 m인 것과 별개다.

모델이 없거나 깨지면 중앙 타원 스텁으로 데모만 된다.
요청 대상이 라벨에 없으면 스텁으로 속이지 않고 실패로 알린다.

## 상세 기능

해석 체인은 LLM과 키워드 파서가 대상에서 다르면 다시 물어 다수결한다.
처음 보는 문장에서 86.7%였던 완전 일치가 96.7%까지 올라간 기록이 그 체인이다.
키워드 파서만의 대상 정확도는 예전 56.6%에서, 역할 규칙(남길 것, 뺄 것, 지울 것) 이후 평가 문장에서 100%에 가깝게 맞았다. 효과는 96.2%였다.

RAG는 콘솔이 승인한 교정, 좋아요, 회원 요청 중 비슷한 문장을 시스템 지시 뒤에 예시로 붙인다.
검색은 글자 2그램과 3그램의 TF-IDF다. 외부 임베딩을 받지 않는다.
승인 뒤 약 30초 안에 색인이 바뀐다. 다른 사용자의 문장 원문은 결과 메타에 남기지 않고 출처와 점수만 남긴다.
학습 시드 800건을 예시로 넣으면 오히려 점수가 내려가, 시드는 기본에서 빼 두었다. 임계값은 0.6으로 높다.

LoRA는 GPU에서 283문장 94.7%, 문장당 약 1초였다. 같은 비교에서 Ollama 체인은 85% 근처였다.
그래도 운영 기본은 Ollama다. 홀드아웃에서는 Ollama 체인이 더 높은 구간이 있었고, ARM 서버에는 GPU가 없다.
`PROMPT_SECOND_OPINION`으로 LoRA를 먼저 쓰고 갈릴 때만 Ollama를 부르는 혼합은 253문장에서 91.3%, 3.0초였다. 기본값으로 올리지는 않았다.

영상 추적은 서로 지나가도 첫 프레임의 대상을 유지하는 쪽이다. 실제 DAVIS 영상에서 맞은 비율이 72.8%에서 92.1%로 올랐다.
닮은 사람이나 오래 가려지는 경우는 한계로 가이드에 적혀 있다.

## 학습으로 이어지는 API와 스크립트

런타임 API:

| 호출 | 학습에서의 의미 |
|------|-----------------|
| `POST /api/v1/feedback` | 좋아요, 싫어요, 정답 JSON |
| 회원 업로드 | `LEARNING_COLLECT_REQUESTS`이면 문장과 해석이 검수 후보 |
| `POST /api/v1/chat` | 학습에 넣지 않음. 대화 비저장 |
| 콘솔 검수 API | 승인된 것만 RAG와 재학습 입력 |

스크립트는 요청 경로가 아니다. 운영자가 돌린다.

| 스크립트 | 하는 일 |
|----------|---------|
| `scripts/retrain_lora.py` | 증강, 학습, 평가 세트 판정, `--deploy` |
| `scripts/retrain_yolo.py` | 어려운 사례로 이어 학습. COCO만으로는 채택되지 않은 기록이 있다 |
| `scripts/seg_labeling.py` | 실패 사진을 Label Studio용으로 내보내기. 외부 라벨 서비스에는 올리지 않는다 |
| `scripts/pseudo_labeling.py` | 오픈 보캐브로 라벨 후보 |
| `training/yolo/apply_best.py` | 채택 가중치를 `backend/models`로 복사 |

`prompt_spec.py`를 바꾸면 LoRA를 다시 학습해야 한다. 지시문과 정답 형식이 그 파일이기 때문이다.

## 내부에서 확인하는 장면

AI가 맞는지는 화면의 "이렇게 이해했어요" 칩으로 본다. 대상, 위치, 색, 남기기와 지우기가 문장과 같은지다.
틀리면 회원이 정답을 보내고, 콘솔 학습 화면에서 그 후보를 승인하거나 고친다.
포트폴리오 사이트의 AI 장은 그 칩이 보이는 작업실, 학습 검수 화면, 그리고 실험 문서의 전후 그림을 인용한다.
가중치 파일 자체는 저장소에 없다.

## 고급 기술

LangChain은 문장 해석의 다수결에 쓴다. 에이전트 도구 호출의 긴 체인은 아니다.
LangGraph는 업로드 한 건의 상태 기계다. 재시도와 최선 시도 선택이 이유다.
RAG는 벡터 데이터베이스가 아니다. 승인 문장 목록을 메모리에서 다시 색인한다.

포트폴리오 Flask 안내는 같은 이름을 다른 목적으로 쓴다.
LangGraph로 질문 분류, 검색, 답변을 나누고, LangChain으로 Ollama `gemma4:12b`를 호출하고, 이 폴더의 마크다운과 핵심 제품 문서를 검색한다.
대화는 서버에 쓰지 않는다. 브라우저 `localStorage`가 기록을 가지고, 요청마다 최근 대화를 다시 보낸다.
제품의 `POST /api/v1/chat`과는 프로세스도 모델 기본값도 다르다. 제품 챗의 기본 선택지는 e4b이고, 안내 챗은 12b로 고정해 설명 품질을 우선한다.
12b가 이 PC에 없으면 안내 챗은 그 사실을 말하고, 사진을 처리하는 제품 기능은 그대로 e4b를 쓴다. 제품 설정을 안내 챗이 바꾸지 않는다.

## 문제와 개선

- PC가 꺼지면 운영 해석이 키워드 파서로 떨어진다.
- 12b와 27b는 느리고, Worker 제한에 걸린다.
- 오픈 보캐브는 측정만 되어 있고 가중치가 없다.
- 세그 재학습은 실패 사진이 쌓인 뒤에야 의미가 있다. COCO만 추가 학습한 실행은 채택하지 않았다.
- 움직이는 카메라 지우기는 아직 클립의 일부가 옛 방식이다.
- 라벨을 COCO나 YOLO 형식으로 사용자에게 주는 기능은 예정이다. 프로젝트의 원래 목적(학습 데이터 준비)에 가장 가깝다.
- 브라우저 로컬 추론과 추출한 대상을 다른 배경에 붙이는 편집기는 그다음이다.

추가하려는 추론 서버:

- NVIDIA GPU가 있는 백엔드 오버레이. 이미 `docker-compose.gpu.yml`이 있다. 운영 ARM 서버와는 다른 기계다.
- 그때 LoRA를 기본 해석으로 올릴지 다시 측정한다. 문서의 숫자는 GPU 측정이다.
- 오픈 보캐브는 가중치를 받은 뒤에만 켠다. 자동으로 큰 모델을 받지 않는다.

## 이후 방향

해석은 로컬을 기본으로 둔다. 사진을 외부 모델에 보내지 않는다.
문장만 외부로 보내는 설정은 가능하지만, 처리방침과 함께 켤 일이다.
정확도는 모델 교체보다 검수된 문장과 실패 사진에서 더 오른다.
안내 챗은 그 사실을 문서에 있는 대로만 말한다. 저장소에 없는 기능을 있다고 하지 않는다.
