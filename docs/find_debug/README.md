# find_debug — 날짜별 디버깅 기록

> 작업 · 실행 중 만난 버그를 **그날 그날** 남긴다. 증상 → 원인 → 해결 → 재발 방지.

다시 날 수 있는 인프라 장애를 증상별로 정리한 것은 [`../repeater/`](../repeater/README.md)다. 이 폴더는 시간 순 일지이고, 여기서 반복되는 문제가 보이면 `repeater/`로 옮겨 정리한다.

## 목록

| 날짜 | 파일 | 다룬 문제 |
|------|------|-----------|
| 2026-07-27 | [2026-07-27.md](./2026-07-27.md) | 첫 Docker 기동 — Redis 6379 포트 충돌 · 백엔드 `ImportError: engine` (→ `repeater/`로 정리됨) |
| 2026-09-29 ~ 30 | [2026-09-29.md](./2026-09-29.md) | Windows 셸에서 curl 한글 깨짐 · `--reload` 감시 경로 · 페이징과 메모리 부족(OOM) · 평가 데이터 누수 · 작업 기록 500(백엔드 꺼짐) |

그 뒤의 장애는 대부분 [`../repeater/`](../repeater/README.md)와 인수인계 문서의 "겪은 함정"([`../HANDOVER.md` 7절](../HANDOVER.md))에 정리되어 있다.

## 규칙

1. 파일명은 `YYYY-MM-DD.md` (하루 단위로 추가 · 갱신, 며칠에 걸치면 시작일)
2. 이슈마다 **증상 / 원인 / 해결 / 재발 방지** 네 구역을 쓴다
3. 재현 명령과 로그 원문은 코드 블록으로 남긴다 (비밀 값은 지운다)
4. 원인을 확인하지 못했으면 "추정"이라고 적는다

## 템플릿

```markdown
# Debug log — YYYY-MM-DD

## 1. <증상 한 줄>

- 증상: …
- 원인: …
- 해결: …
- 재발 방지: … (테스트 · 문서 · 점검 스크립트)
```
