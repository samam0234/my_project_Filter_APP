## Issue 1 — Git Bash curl 로 보낸 한글 프롬프트가 깨짐

### 증상
`curl -F "prompt=버스만 남기고 배경 블러" …/api/v1/upload` 결과 `parsed_prompt.target` 이 `["person"]`.
같은 문장을 Python 에서 직접 LLM 에 넣으면 `["bus"]`.

### 원인
Windows Git Bash 의 curl 이 multipart 필드를 시스템 코드페이지(cp949)로 보내 서버에서 글자가 깨짐.
코드 문제가 아니다.

### 해결
테스트는 UTF-8 로 본문을 직접 만드는 Python 클라이언트로 전송.

```python
body = …prompt.encode("utf-8")…   # multipart 를 직접 조립
urllib.request.urlopen(Request("http://localhost:8000/api/v1/upload", body, {...}))
```

### 재발 방지
- 한글 프롬프트 API 스모크는 브라우저(프론트) · Swagger `/docs` · Python 으로 한다

## Issue 2 — `--reload` 서버가 브랜치 체크아웃에 따라 다른 DB·모델을 봄

### 증상
폴더 분리 작업 중 실행 중이던 uvicorn(`--reload`)이 자동 재시작되며
`backend/data/cutnkeep.db` 를 **빈 DB** 로 새로 만들고, `backend/models/` 에 가중치가 없어 stub 세그로 동작.

### 원인
`--reload` 는 작업 폴더의 코드 변경(브랜치 체크아웃 포함)을 즉시 반영한다.
경로 기준이 저장소 루트 → `backend/` 로 바뀐 코드가 올라온 것.

### 해결
기존 DB 를 SQLite online backup 으로 복사하고 jobs 의 before/after 절대 경로를 새 위치로 갱신,
uploads·가중치 복사 (원본 유지).

### 재발 방지
- 서버를 띄운 채 다른 브랜치 작업이 필요하면 `git worktree` 로 분리
- 경로 규칙을 바꾸는 커밋은 기록에 "데이터 이전" 절차를 남긴다

## Issue 3 — 업로드가 `INVALID_PROTOBUF` 로 failed

### 증상
`/api/v1/upload` 응답 `status: failed`, `parsed_prompt: null`. 로그:

```text
Ultralytics 로드 실패: [WinError 1455] 이 작업을 완료하기 위한 페이징 파일이 너무 작습니다 … nvperf_host.dll
파이프라인 실패: [ONNXRuntimeError] : 7 : INVALID_PROTOBUF : Load model from …\yolo26s-seg.pt failed
```

### 원인
1. LoRA 학습 + Ollama + 백엔드가 동시에 돌며 RAM(16 GB) 커밋 한도 부족 → torch DLL 로드 실패
2. 그 뒤 Segmentor 가 `.pt` 를 onnxruntime 으로 열려다 예외 → 파이프라인 전체 실패 (stub 폴백 안 됨)

### 해결
- `onnx_utils.create_session`: `.onnx` 확장자만 세션 생성, 로드 예외도 `None` → stub 폴백
- 학습 종료 후 서버 재기동으로 torch 정상 로드

### 재발 방지
- 로컬에서 LoRA 학습 중에는 백엔드 요청을 피하거나 Ollama 모델을 내린다 (`ollama stop gemma4:e4b`)
- 테스트: `test_create_session_skips_non_onnx`
