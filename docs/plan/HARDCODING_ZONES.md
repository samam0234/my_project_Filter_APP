# 하드코딩 구간 · 완성도 부족분 맵

**목적:** 빈 칸을 어디에 채우는지 + **이미 구현(바이브) vs 하드코딩** 을 코드에서 구분한다.

---

## 0. 코드 안 구간 표시 규칙 (필수)

### 하드코딩 (네가 작성)

```text
# =============================================================================
# [하드코딩 파트] 작업 이름
# -----------------------------------------------------------------------------
# [임무] ...
# [연결] ...
# [규칙] ...
# [힌트] ...
# =============================================================================
# >>> 여기에 작성 <<<
#
```

### 이미 구현 (바이브 / 스캐폴드 완료)

```text
# =============================================================================
# [이미 구현된 구간 · 바이브] 짧은 설명
# -----------------------------------------------------------------------------
# 에이전트·스캐폴드가 채운 동작 코드. 하드코딩 숙제 아님.
# =============================================================================
(실제 코드)
```

| 표시 | 의미 |
|------|------|
| `[하드코딩 파트]` | 직접 구현 대상 |
| `[이미 구현된 구간 · 바이브]` | 이미 돌아가는 코드 (읽기·참고) |
| `# >>> 여기에 작성 <<<` | 커서 둘 위치 |
| `=============` 긴 줄 | 블록 경계 (격차) |

두 구간이 이어질 때 **사이에 빈 줄 1줄** 유지.

---

## 1. 완성도 스케치 → 부족분

| 영역 | 대략 현재 | 부족 | 채울 하드코딩 (우선) |
|------|-----------|------|----------------------|
| 골격·인프라·문서 | ~80% | ~20% | 코드 아님 (.env, 모델 파일) |
| Phase1 단일 이미지 | ~70% | ~30% | **LLM 연결**, (선택) ONNX |
| 비전 품질·학습 루프 | ~30% | ~70% | 데이터, **평가**, **pseudo**, YOLO fine-tune |
| Phase2 | ~20% | ~80% | **배치**, **LoRA**, **DINO+SAM2** |

**권장 순서:** LLM → 모델 배치 → ONNX(선택) → 학습·평가 → batch → pseudo → LoRA → SAM2
