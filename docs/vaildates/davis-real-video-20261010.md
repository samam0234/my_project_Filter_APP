## 왜

앞선 영상 평가는 모두 합성이었다. 사진 배경에 사람을 붙여 옆으로 일정하게 걷게 했다
([`video-tracking-hard-20261009.md`](./video-tracking-hard-20261009.md) · [`video-removal-pan-20261009.md`](./video-removal-pan-20261009.md)).
실제 영상에는 손떨림 · 시차 · 조명 변화 · 자세 변화 · 군중이 있다. 그래서 합성에서 잘 된 것이 실제로도 되는지 다시 쟀다.

## 1. 추적 — "가장 왼쪽 사람"을 끝까지

- 대상 영상: 첫 프레임에서 정답 객체 중 사람(YOLO 사람 검출과 IoU 0.5 이상)이 둘 이상인 영상 15개. 그중 채점한 것은 11개다
  - 4개는 뺐다(color-run · dancing · india · judo). 첫 프레임에 고른 사람이 정답 객체가 아니었다
  - DAVIS 는 주요 인물만 그리므로, "가장 왼쪽"이 정답 없는 군중 속 사람일 수 있다
- 대상은 첫 프레임에서 시스템이 고른 사람에 대응하는 정답 객체다(IoU 0.5 이상). 추적이 약속하는 것은 "처음 고른 그 사람을 유지"이기 때문이다
- 맞음: 대상 IoU 0.1 이상이고, 다른 정답 객체보다 대상과 더 겹칠 때다. 대상이 15% 미만으로 보이는 프레임은 채점에서 뺐다
- 세그는 실제 YOLO26m-seg 다

### 실제 영상에서 찾아 고친 것

| 영상 | 증상 | 고친 것 (`instance_tracker.py`) |
|------|------|-------------------------------|
| walking | 대상이 17프레임 사라졌다 작게 다시 들어오면, 일부만 보여 색으로 다시 찾기에 실패했다. 그동안 직전 자리를 들고 있었다 | 오래 놓친 뒤 색으로 못 찾으면, **이미 따라가는 다른 사람이 아닌 새로 나타난** 사람 중 selector 가 고르는 사람으로 이어 간다(`_newcomer`) |
| walking | 위 규칙이 작은 오검출(수십 픽셀)을 대상으로 잡았다. 그 뒤 진짜 대상으로 "점프"한 것이 속도로 남아 다시 놓쳤다 | 새 사람은 평소 대상 면적의 15% 이상만 인정(`NEWCOMER_MIN`), 예측 속도에 상한(`MAX_SPEED`) |
| walking | 다시 들어오며 커지는 대상을 "옆 사람과 합쳐짐"으로 오해해 기준 모습을 갱신하지 않았다. 근처의 작은 오검출 추적과 겹쳤기 때문이다 | 합쳐짐은 **사람 크기만 한** 다른 추적과 겹칠 때만 인정 |

### 시도했지만 되돌린 것

- **중복 조각 합치기**(대상과 크게 겹치는 다른 마스크를 합쳐 씀): upside-down · drone IoU 는 그대로였고 disc-jockey 가 1.00 → 0.93 으로 내려갔다
- **다시 잡는 범위를 대상 크기에 비례**: drone 이 0.93 → 0.77 로 내려갔다
- 영상 11개에 맞춰 규칙을 계속 늘리면 이 표본에만 맞는다. 그래서 위 세 가지에서 멈췄다

### 남은 약점

- **빠르게 모양 · 크기가 바뀌는 대상**(upside-down 곡예, drone 의 가까워지는 사람)은 대상을 맞게 따라가도 IoU 가 낮다(0.80 → 0.66)
  - 예측 위치와의 겹침이 기준 아래로 떨어지면 잠깐 직전 마스크를 들고 있기 때문이다
- **군중(schoolgirls)**은 둘 다 낮다. 사람끼리 계속 겹치고 검출이 자주 합쳐진다

## 2. 지우기 — 실제 카메라 움직임에서 배경판

실제 DAVIS 영상(앞 40프레임) 30개에 다른 COCO 사진의 사람을 잘라 붙여 가로질러 걷게 하고 지웠다. **원래 영상이 정답**이다.
그래서 진짜 손떨림 · 시차 · 조명 변화가 들어간다. 원래 영상의 움직이는 물체(DAVIS 정답 객체) 자리는 채점에서 뺐다.
깜빡임은 "결과의 프레임 간 변화 − 원래 영상의 프레임 간 변화"(절댓값)로 쟀다.

| 쓴 방식 (영상 수) | L1 구멍 안 (예전 Telea → 지금) | 깜빡임 |
|-------------------|-------------------------------|--------|
| 맞춤 불가 → 예전 방식 (18) | 23.0 → 23.0 | 6.5 → 6.5 |
| 고정 카메라 배경판 (7) | 18.0 → **13.0** | 9.4 → **5.3** [−8.5, −0.6] |
| 맞춤 배경판 (5) | 20.2 → **18.9** [−2.9, −0.2] | 4.4 → 4.8 (약간 나빠짐) |
| **전체 (30)** | 21.4 → **20.0** [−3.3, −0.1] | 6.8 → **5.95** [−2.1, −0.0] |

- **30개 중 18개는 프레임 맞춤 판정에서 걸려 예전 방식으로 갔다.** 실제 영상의 시차 · 흔들림은 한 평면 변환으로 맞지 않는다
  - 안전장치가 의도대로 동작한 것이고, 동시에 이 개선의 한계다
  - 합성 영상에서는 팬 · 확대가 거의 다 맞춤으로 갔다
- 좋아진 예: crossing 35.5 → 11.0, drift-chicane 9.7 → 4.8, bike-packing 24.7 → 17.5
- 나빠진 예: disc-jockey 14.5 → 17.9(공연 조명 · 군중), dogs-jump 14.3 → 14.9, boat 13.5 → 14.0

### 실제 영상에서 찾아 고친 것 (`video_inpaint.py`)

1. **배경판을 시간 중앙값으로**: 평균은 원래 영상의 다른 움직이는 물체를 섞는다
   - 고르게 남긴 최대 9장 표본(`PLATE_SAMPLES`)의 중앙값을 쓴다. 3장 이상에서 보인 픽셀에만 쓰고, 나머지는 평균이다
   - 합성 확대 L1 9.0 → 8.4, 맞춤 깜빡임 6.6 → 5.2
2. **밝기 맞춤**: 구멍 바로 바깥 띠에서 지금 프레임과 배경판의 채널 평균 차를 재 배경판을 맞춘다(상한 40)
   - 다른 시점의 배경이라 조명 · 노출이 다르다. disc-jockey 35.6 → 28.6
3. **프레임별 안전장치**: 밝기를 맞춰도 띠의 차가 18을 넘으면 그 프레임만 예전처럼 Telea 로 메운다(`RING_MAX`)
   - 조명 · 군중이 계속 바뀌는 장면용이다. disc-jockey 28.6 → 17.9
   - 전체 차이가 이 단계에서 처음으로 신뢰구간 0 밖으로 나갔다
   - 대신 배경판과 Telea 가 섞인 영상은 깜빡임이 늘 수 있다(bike-packing 1.6 → 12.0)

### 시간

- 맞춤 배경판은 느리다. bear(40프레임, 480p) 2.6초 → 22.4초. 특징점 맞추기와 표본 저장 때문이다
- 고정 카메라는 1~3초 늘어난다

## 정리

- **추적**: 실제 영상에서도 확실히 낫다(맞은 비율 +19%p)
- **지우기**: 실제 영상에서는 효과가 작다(L1 −1.4). 고정 카메라에서는 확실히 낫고(L1 18.0 → 13.0), 움직이는 카메라는 대부분 예전 방식이다
  - 실제 카메라 움직임에서 크게 좋아지려면 다른 방법이 필요하다(광학 흐름 기반 채우기 · 학습형 영상 인페인팅). 지금 구조에서는 다음 단계로 남긴다
