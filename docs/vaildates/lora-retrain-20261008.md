# LoRA 재학습 — 방해물 문장 시드 반영 (2026-10-08)

> 실행: `python scripts/retrain_lora.py --force` · 실행 이름 `user_261008_1509` · 원자료 [`lora_retrain_20261008.json`](./lora_retrain_20261008.json)  
> 배경: [`leak-diagnosis-20261008.md`](./leak-diagnosis-20261008.md) — "X 말고 Y만"처럼 지정하지 않은 대상이 같이 언급되는 문장을 LLM 이 대상에 섞는 문제

## 요약

- 방해물 학습 문장 180개(`train_distractor.jsonl`)를 넣어 다시 학습했다. **방해물 문장의 대상 정확도는 78.7%에서 95.7%로**, 규칙을 만든 뒤 쓴 홀드아웃 문장은 70.0%에서 87.5%로 올랐다
- 재학습 판정(다섯 평가셋에서 1문항 넘게 떨어진 곳 없음 + 전체 개선)을 통과했다: 전체 **+17문항**, 최대 하락은 `eval_ext` 1문항. 배포본(`backend/models/lora`)을 교체했고 이전 배포본은 `backend/models/lora_prev_261008_1543` 에 있다
- **하지만 LoRA(1.5B)는 아직 기본 LLM(Ollama gemma4 + 해석 체인)보다 약하다.** 처음 보는 30문장 대상 정확도는 LoRA 73.3%, 체인은 96.7%. 그래서 **기본 `LLM_PROVIDER` 는 ollama 그대로 둔다.** LoRA 는 Ollama 를 띄울 수 없는 환경의 대안이다

## 해석과 한계

- 방해물 문장과 홀드아웃이 크게 오른 것은 학습에 넣은 "X 말고 Y만" 패턴이 일반화된 결과다. 학습 문장과 평가 문장은 겹치지 않는다
- `eval_fresh` 는 3.3%p(1문항)만 올랐다. 틀린 것은 대부분 시드에 없는 어휘 조합이다(예: "자전거 탄 사람은 두고 도로만 흐리게" → 대상을 `road` 대신 `bicycle rider` 로 답함). 표현 다양성을 늘리려면 승인 문장이 더 쌓여야 한다. 지금 승인 문장은 8개뿐이다
- 손실 0.0034 는 낮다. 학습 문장을 외웠을 수 있지만, 처음 보는 문장 셋들에서 떨어지지 않았으므로 판정을 그대로 따랐다
- 평가셋이 30~56문장이라 1~2문항 차이는 잡음 범위다. 판정 규칙이 1문항 하락까지 허용하는 이유다
