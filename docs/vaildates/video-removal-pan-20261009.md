# 영상 · GIF 대상 지우기 — 카메라가 움직여도 배경판 쓰기 (2026-10-09)

> 도구: [`scripts/experiments/video_removal_eval.py`](../../scripts/experiments/video_removal_eval.py) · 원자료 [`video_removal_pan_eval_20261009.json`](./video_removal_pan_eval_20261009.json) · 코드 `backend/app/services/video_inpaint.py`
> 앞 단계: [`video-removal-20261009.md`](./video-removal-20261009.md) (고정 카메라 배경판)

## 문제

고정 카메라 영상은 다른 프레임에서 보인 배경으로 지운 자리를 채운다. 카메라가 움직이면 배경판이 어긋난다. 그래서 예전처럼 프레임마다 Telea 로 메웠고, 큰 물체는 번진 얼룩과 깜빡임이 그대로 남았다.

## 바꾼 것 — 프레임 맞추기(aligned)

1. 연속 프레임 사이 호모그래피를 구한다
   - 대상 자리는 빼고 ORB 특징점 1,500개를 찾는다
   - 비율 검사(0.75)를 거친 뒤 RANSAC 으로 맞춘다
   - 긴 변 640px 로 줄여서 계산한다
2. 이 호모그래피를 이어 붙여 모든 프레임을 **기준 좌표의 넓은 캔버스**에 맞춘다. 캔버스는 사방으로 긴 변의 25% 만큼 넓다. 마스크 밖 배경을 여기에 모은다
3. 맞춤 방식을 쓸지 판정한다. 아래를 모두 만족해야 쓴다
   - 맞춘 뒤 남는 프레임 간 차이가 고정 카메라와 같은 기준이다(중앙값 < 6, 90 백분위수 < 14)
   - 맞추기 실패가 10% 이하다
   - **시차가 큰 장면**(가까운 층과 먼 층이 다르게 움직임)은 한 번에 맞출 수 없어 이 기준에서 걸린다. 그런 장면은 예전처럼 프레임마다 Telea 로 간다
4. 고정 기준을 넘어도 맞춘 뒤 차이가 맞추기 전의 60% 아래면 맞춤 방식을 쓴다. 느린 확대나 팬이 여기에 해당한다. 진짜 고정 카메라는 두 값이 비슷해서 그대로 고정 방식이다
5. 그릴 때는 캔버스 배경판을 그 프레임 좌표로 되돌린다. 지운 자리를 채우고 경계 2px 를 섞는다
6. 한 번도 안 보인 자리만 캔버스에서 LaMa 로 한 번 메운다. 고정 카메라와 같다

- 1080p 보다 큰 프레임은 맞춤 방식을 쓰지 않는다. 캔버스 누적 메모리가 1080p 에서 약 100MB 다
- 응답의 `removal.mode` 에 `static` · `aligned` · `frame` 중 어느 방식을 썼는지 담긴다

## 평가 — 정답이 있는 합성 영상

COCO 사진(사람 없는 것)을 배경으로 쓰고, 다른 사진의 사람을 잘라 붙였다. 16프레임, 긴 변 480px 이고, 시나리오마다 20개다. 원래 배경이 정답이다.

| 시나리오 | 쓴 방식 | L1 (구멍 안, 예전 → 지금) | PSNR dB | 깜빡임 |
|----------|---------|---------------------------|---------|--------|
| 움직이는 사람 (고정 카메라) | static 20 | 26.4 → **0.0** | 16.9 → 99 | 22.5 → 0.0 |
| 제자리 사람 (배경이 안 보임) | static 20 | 27.3 → 23.8 | 16.6 → 17.4 | 0 → 0 |
| **카메라 옆 이동 (팬)** | aligned 19 · static 1 | 27.5 → **6.9** [−24.5, −17.0] | 16.5 → **27.5** | 5.2 → **2.2** |
| **카메라 확대 (프레임마다 1.2%)** | aligned 15 · static 5 | 26.1 → **9.0** [−21.5, −12.7] | 16.9 → **26.0** | 15.3 → **1.2** |

[ ] 는 쌍 비교 차이의 95% 신뢰구간이다.

- 예전 문서에서 팬은 27.5 → 27.5 로 변화가 없었다(배경판을 못 썼다). 이번에 **27.5 → 6.9** 가 됐다
- 고정 카메라 영상(위 두 줄)은 판정과 결과가 예전과 같다
- 확대 영상 중 5개는 움직임이 아주 작아 고정으로 판정됐다
  - 처음에는 7개였고, 오차는 12.8 이었다(맞춤으로 간 것은 8.4)
  - 4번 규칙(맞춤으로 차이가 확 줄면 맞춤)을 넣어 9.9 → 9.0 으로 줄였다

### 시간

- 1080p 30프레임 측정: 1단계(배경판 만들기)가 프레임당 99ms → 241ms 로 늘었다. 2단계 그리기는 같았다(약 85ms)
- 프레임당 세그 시간(수백 ms)에 더해지므로, 카메라가 움직이는 영상의 전체 처리 시간은 늘어난다

## 한계

- **합성 카메라 움직임은 평면 사진을 옮긴 것이라 호모그래피로 정확히 맞는다.** 실제 영상은 다르다
  - 시차가 있고, 렌즈 왜곡 · 흔들림 블러 · 노출 변화도 있다
  - 그래서 aligned 판정이 덜 나오고, 오차도 이 표보다 클 것이다
- 시차가 큰 장면(앞쪽 사람 · 가까운 물체가 많은 거리)은 판정에서 걸려 예전 방식으로 간다. `tests/unit/test_video_inpaint.py` 의 시차 테스트가 이를 확인한다
- 다른 움직이는 물체(지나가는 차 등)가 배경판에 섞일 수 있다. 고정 카메라 방식과 같은 한계다
