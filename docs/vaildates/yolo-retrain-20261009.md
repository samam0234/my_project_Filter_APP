# 세그 모델(YOLO26m-seg) 재학습 루프 — 첫 실행 (2026-10-09)

> 코드: `scripts/retrain_yolo.py` (수집 → 라벨 → 이어 학습 → 평가 → 판정 → `--deploy`)
> 원자료: [`yolo_retrain_20261009.json`](./yolo_retrain_20261009.json) (두 실행의 시나리오별 점수 · 에폭별 mAP · 설정)
> 배경: [`leak-diagnosis-20261008.md`](./leak-diagnosis-20261008.md) — 맞닿거나 겹친 사람에서 섞임 · 오선택이 남는다

## 요약

- 세그 모델 재학습을 한 명령으로 돌리는 루프를 만들었다. 단계는 수집, 라벨, 학습, 평가, 판정, 배포다
  - 판정 기준 1: 일반 성능(mask mAP)이 0.5%p 넘게 떨어지면 안 된다
  - 판정 기준 2: 어떤 시나리오에서도 선택 정확도와 섞임이 2%p 넘게 나빠지면 안 된다
  - 판정 기준 3: 어려운 시나리오에서 2%p 넘게 좋아진 지표가 있어야 한다
- COCO 의 어려운 사례로 두 번 돌렸고, **둘 다 불채택**이다. 배포 모델은 그대로다
  - 1차: 일반 성능이 무너졌다
  - 2차: 일반 성능은 유지했지만 어려운 사례도 나아지지 않았다
- 원인은 데이터에 있다. 서비스 모델(ultralytics 공개 가중치)은 **이미 COCO train2017 로 학습됐다**. 같은 사진 모음에서 어려운 사례를 다시 뽑아도 새 정보가 거의 없다
  - 실질적인 개선에는 **COCO 밖의 사진**이 필요하다. 서비스에서 실패한 사진에 직접 라벨을 단 것을 말한다
  - 루프는 그 데이터를 `--extra` 로 받는다. 수집 경로는 `HARD_EXAMPLE_CONF` 다. 아래 "다음"에 정리했다

## 데이터

| 구성 | 장수 | 고른 방법 |
|------|------|-----------|
| 어려운 사례 | 1,500 | COCO train2017 에서 화면 2.5% 이상인 인스턴스 둘 이상이 맞닿거나 겹친 사진 (박스를 긴 변 2% 넓혀 겹침 판정) |
| 일반 사진 | 1,500 | 나머지 train2017 무작위 — 다른 클래스를 잊지 않게 섞는 몫 |
| 검증 | 500 | val2017 중 섞임 평가에 쓰지 않는 사진 — mask mAP 비교용 |

라벨은 COCO 폴리곤을 서비스 모델의 80클래스 순서로 바꾼 YOLO-seg 형식이다. 데이터는 git 밖(`training/datasets/yolo_hard/`)에 둔다.

## 결과

섞임 평가는 `leak_eval` 시나리오를 쓴다. COCO val2017 정답을 서빙과 같은 경로로 돌린다. 시나리오마다 48장(dog 32장)이다.

| | 배포 모델 | 1차 (lr0 5e-4 · 앞 10층 고정 · 8에폭) | 2차 (lr0 1e-4 · 머리만 · 6에폭) |
|---|---|---|---|
| **mask mAP50-95** (val 500) | 0.428 | **0.388** ✗ | 0.431 |
| left 선택 정확 | 0.938 | 0.812 | 0.917 |
| rank2 선택 정확 | 0.917 | 0.833 | **0.833** ✗ |
| touching 선택 정확 | 0.917 | 0.833 | 0.917 |
| rank2 섞임 5% 초과 | 0.208 | 0.250 | 0.229 |
| touching 섞임 5% 초과 | 0.167 | 0.146 | 0.146 |
| all_persons 섞임 5% 초과 | 0.109 | 0.156 | 0.085 |
| dog 섞임 5% 초과 | 0.069 | 0.148 | 0.069 |
| 판정 | — | 불채택: 일반 성능 하락 | 불채택: 선택 정확 하락 |

- **1차**는 첫 에폭 만에 mAP 가 0.428 → 0.334 로 무너졌다. 8 에폭 동안 0.390 까지만 회복했다
  - 원인 1: ultralytics 의 기본 워밍업 편향 학습률(0.1)
  - 원인 2: 미세 조정에 비해 큰 학습률
  - 그래서 기본값을 2차 설정으로 바꿨다: 워밍업 끔, 편향 학습률 = lr0, lr0 1e-4, Segment 머리만 학습, mosaic 0.5
- **2차**는 일반 성능을 지켰다(0.428 → 0.431)
  - touching 과 all_persons 의 섞임 5% 초과는 각각 1장씩 줄었다
  - 하지만 rank2 에서 선택이 4장 틀어졌고, 평균 섞임도 0.08 → 0.14 로 늘었다
  - 48장에서 1~2장 차이는 잡음 범위다. 판정 규칙대로 채택하지 않았다

## 운영 중 겪은 문제

- 학습 데이터 로더 작업자 8개로 돌리자 Windows 호스트 메모리(16GB, 여유 약 5GB)가 모자라 1 에폭 뒤 `MemoryError` 로 멈췄다
  - Windows 는 작업자마다 프로세스를 새로 띄운다
  - 그래서 `--train-workers` 를 추가하고 기본값을 2 로 했다. 에폭당 약 100초였다
- 작업자 프로세스는 스크립트 파일을 다시 읽는다. 학습 중에는 `scripts/retrain_yolo.py` 를 옮기거나 지우면 안 된다

## 다음 — 실제로 나아지려면

1. **COCO 밖 실패 사진 모으기**: `HARD_EXAMPLE_CONF=0.4` 를 켜면 신뢰도가 낮은 회원 요청이 학습 후보로 모인다(`learning-loop.md` ⑥)
   - 0.4 기준이면 사진의 약 10% 가 걸리고, 그중 31% 가 실제 섞임이나 오선택이다
   - 다만 회원 이미지를 더 저장하게 되므로 개인정보 안내와 함께 결정해야 한다
2. **라벨 달기**: 모인 사진을 CVAT · Label Studio 등에서 YOLO-seg 폴리곤으로 내보낸다. 폴더 구조는 `images/` · `labels/` 다
3. **돌리기**: `python scripts/retrain_yolo.py --skip-collect --extra <라벨 폴더>`
   - COCO 어려운 사례와 일반 사진에 실패 사진이 더해진다
   - 판정 규칙은 그대로다
   - 수백 장 단위가 모였을 때 의미가 있다
4. 평가셋이 시나리오당 48장이라, 2%p 기준은 1장 차이다. 실제 개선을 가르려면 평가 사진도 늘려야 한다(`leak_eval.py --download`)
