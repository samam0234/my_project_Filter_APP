## 조합형 문장 (`training/lora/seed/build_compositional.py`)

정답 규칙은 기존 시드 · 평가셋과 같게 맞췄다. 문장 899개를 결정적으로 만든다.

| 묶음 | 비중 | 예 |
|------|------|----|
| 대상 둘 | 26% | "오븐이랑 케이크 빼고 다 투명하게 해줘" → [oven, cake] remove_bg |
| 방해물 | 24% | "식탁은 두고 서핑보드만 흐리게" → [surfboard] blur |
| 관계 표현 | 16% | "소파 위에 있는 포크만 잘라내 줘" → [fork] crop, selector 없음 |
| 탄 사람 | 4% | "스케이트보드 탄 사람은 두고 스케이트보드를 지워줘" |
| 자르기 말 | 12% | "오렌지만 오려내 줘" → crop · "X만 남기고 크롭까지" → remove_bg + crop |
| 어휘 | 18% | COCO 70개 + 배경 덩어리 11개의 한국어 · 영어 이름 |

- 조사(이랑/랑, 은/는, 을/를, 과/와)는 받침에 맞춘다. 기존 시드에 있던 "병랑" 같은 어색한 조사가 생기지 않는다
- 정답 대상 이름이 서빙 규격(`normalize_parsed`)과 같은지, 평가셋 문장과 겹치지 않는지는 `tests/unit/test_retrain_data.py` 가 확인한다

## 해석과 한계

- **`eval_fresh` 의 상승은 부풀려졌을 수 있다.** 이 셋의 오답 유형을 보고 생성기를 설계했기 때문이다
- **`eval_fresh2` 도 완전히 독립적이지는 않다.** 생성기 전에 썼지만, 같은 작성자가 같은 정답 규칙으로 썼다. 실제 사용자 문장과 가장 가까운 지표는 승인된 val 문장이다. 하지만 아직 1개뿐이다. 운영 콘솔에서 승인 문장이 쌓이면 그 점수를 우선해야 한다
- 남은 오답은 대부분 개수와 위치가 섞인 selector 다
  - "오른쪽 개 두 마리만" → 정답은 count 2인데, rank 2 까지 붙였다
  - "새 두 마리 중에 큰 새만" → 정답은 largest 인데, 속성 "large bird" 로 답했다
  - 조합형 문장에 selector 를 넣지 않았으므로 이 부분은 기존 시드(`train.jsonl`) 몫이다
- "하늘 빼고 나머지 전부 투명하게" 를 `person` 으로 답하는 것처럼, 배경 덩어리 하나만 남기는 문장은 아직 흔들린다
