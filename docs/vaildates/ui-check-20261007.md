## 브라우저로 확인해서 찾은 문제

| 발견 | 내용 | 조치 |
|------|------|------|
| **모든 avi 업로드가 400** | 브라우저가 `.avi` 를 `video/avi` 로 보내는데 백엔드는 `video/x-msvideo` 만 허용 ("영상 MIME 이 아닙니다"). 단위 테스트는 허용 값을 그대로 써서 통과했었다 | `video/*` · octet-stream 허용 + **내용 시그니처**(AVI·MP4/MOV·WebM/MKV) 검사. 브라우저가 실제로 보내는 MIME 4종 · 가짜 파일 · 확장자/MIME 불일치 테스트 추가 |
| UI 확인 정리가 배치·영상을 안 지움 | 첫 실행이 배치 행 1건과 `uploads/batches` 폴더를 남김 | `ui_check.py` cleanup 이 배치(DB+폴더)·영상(owner.json 기준)까지 삭제, 남은 것 수동 삭제 |
| **테스트가 실제 업로드 폴더를 오염** | `test_access` 의 배치 테스트가 `backend/data/uploads/batches/` 에 폴더 4개를 남김 (어제 밤 Grok 의 실행 포함) — 피드백 폴더 오염과 같은 유형 | 공용 `api_env` fixture 가 업로드 폴더를 임시 폴더로. 전체 테스트 후 `uploads/batches` 0개 확인 |
| 파일이 없을 때 버튼이 "0장 처리 시작" | 문구 | 파일이 없으면 "처리 시작" |

## 참고

- 학습 DB 는 MariaDB(Docker)가 꺼져 있어 `sqlite(fallback)` 로 확인 — 콘솔 사이드바에 노란색으로 표시됨
- 영상 결과(avi)는 브라우저에서 바로 재생되지 않아 **다운로드까지만** 확인했다. 재생 확인은 하지 않음
- 화면 캡처는 저장소에 넣지 않는다
