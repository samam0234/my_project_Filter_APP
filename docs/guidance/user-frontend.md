- 경로: `frontend/` · 포트: **5173** · 구조 상세: [`frontend/README.md`](../../frontend/README.md)

cd frontend
npm install

## 작업실 사용 흐름

화면 왼쪽은 **1 사진 올리기 → 2 무엇을 남기거나 지울까요? → 3 처리하기** 단계로 나뉘고, 끝낸 단계는 숫자 배지가 채워진다.
처리 시작을 못 누를 때는 이유("먼저 사진을 올려 주세요")가 버튼 아래에 나온다. 넓은 화면에서는 오른쪽 결과 칸이 스크롤을 따라온다.

1. 이미지를 드래그하거나 클릭해 올린다 (JPEG/PNG/WebP, 20MB · 40MP 이하). 올린 뒤 다시 누르면 다른 사진으로 바꾼다
2. 문장을 쓰거나 예시 칩을 누른다 — 예: *"맨 앞에 빨간 안전모 쓴 사람만 남기고 배경 제거"*
3. **처리 시작** (또는 Ctrl+Enter). 진행 칸에 경과 시간과 3단계(문장 해석 → 대상 찾기 → 효과 적용) 막대가 보인다
   - 보통 10~30초, 서버를 켠 뒤 첫 요청은 모델 로드로 더 걸린다
4. 결과 확인
   - **이렇게 이해했어요** 칩: 서버가 문장을 어떻게 해석했는지 (대상 · 위치/개수 · 색 · 남기기/지우기)
   - 상태가 **실패**면 이유가 노란 박스에 나온다 (예: "요청한 대상(bus)을 찾지 못했습니다. 감지된 대상: car, person")
   - **결과 저장**: 배경 제거는 투명 PNG, 나머지는 JPEG
   - 대상 지우기는 학습형 인페인팅(LaMa)으로 주변 무늬를 이어 그려 메운다 (사진 1장에 약 1초 더 걸림)
5. 평가 (로그인 회원 — 비로그인 결과는 저장되지 않아 평가 없이 다운로드만)
   - 좋아요 / 싫어요
   - **정답 알려주기**: 해석이 틀렸으면 올바른 값을 골라 보낸다 → 문장 해석 모델(LoRA) 재학습 데이터

작업실 입력과 결과는 다른 메뉴에 다녀와도 유지된다 (새로고침하면 초기화).

### GIF 탭

1. 작업실 위쪽 **GIF** 탭 → 움직이는 GIF 를 올린다 (20MB, 한 프레임 4MP 이하)
2. 문장은 사진 탭과 같이 쓴다 (탭을 바꿔도 유지). 모든 프레임에 같은 요청을 적용한다
3. **GIF 처리 시작** — 프레임마다 처리하므로 프레임 수에 비례해 걸린다 (480×360 · 10프레임 약 4초)
4. 결과
   - 프레임 간격 · 반복은 원본 그대로, 120프레임이 넘으면 앞부분만 처리하고 알려 준다
   - 배경 제거는 **투명 GIF**. GIF 는 반투명이 없어 경계가 거칠어 **WebP 저장 (부드러운 경계)** 도 함께 준다
   - 처리 전에 **"어디에 올리나요?"** 에서 밝은 배경 · 어두운 배경을 고르면 GIF 경계를 그 색에 맞춰 부드럽게 만든다 (반대 배경에 올리면 테두리가 보임 — 모르면 "정하지 않음")
   - 회원은 작업 기록에 GIF 로 남고(움직이는 썸네일), 비로그인은 바로 내려받기만

## 디자인

다크 테마 + 하늘색(brand) 포인트, 한국어 글꼴 **Pretendard**(빌드에 포함, 외부 CDN 없음), 한국어 낱말 단위 줄바꿈(`keep-all`).
공통 모양은 `src/index.css` 의 `card` · `field` · `eyebrow` · `step-dot` 클래스와 `buttonClass()` 로 맞춘다 — 화면을 새로 만들 때 이것부터 쓴다.
키보드 초점 링 통일, 움직임 줄이기 설정 존중. 이전/이후 화면: [`docs/vaildates/ui-design-20261008.md`](../vaildates/ui-design-20261008.md)
