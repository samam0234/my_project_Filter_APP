# User Frontend 가이드

- 경로: `frontend/` · 포트: **5173** · 구조 상세: [`frontend/README.md`](../../frontend/README.md)

```bash
cd frontend
npm install
npm run dev
```

프록시: `/api`, `/health` → `localhost:8000` (백엔드가 먼저 떠 있어야 함)

## 작업실 사용 흐름

1. 이미지를 드래그하거나 클릭해 올린다 (JPEG/PNG/WebP, 20MB 이하)
2. 문장을 쓰거나 예시 칩을 누른다 — 예: *"맨 앞에 빨간 안전모 쓴 사람만 남기고 배경 제거"*
3. **처리 시작** (또는 Ctrl+Enter). 진행 배너에 경과 시간과 단계가 보인다
   - 보통 10~30초, 서버를 켠 뒤 첫 요청은 모델 로드로 더 걸린다
4. 결과 확인
   - **이렇게 이해했어요** 칩: 서버가 문장을 어떻게 해석했는지 (대상 · 위치/개수 · 색 · 남기기/지우기)
   - 상태가 **실패**면 이유가 노란 박스에 나온다 (예: "요청한 대상(bus)을 찾지 못했습니다. 감지된 대상: car, person")
   - **결과 저장**: 배경 제거는 투명 PNG, 나머지는 JPEG
5. 평가 (로그인 회원 — 비로그인 결과는 저장되지 않아 평가 없이 다운로드만)
   - 좋아요 / 싫어요
   - **정답 알려주기**: 해석이 틀렸으면 올바른 값을 골라 보낸다 → 문장 해석 모델(LoRA) 재학습 데이터

작업실 입력과 결과는 다른 메뉴에 다녀와도 유지된다 (새로고침하면 초기화).

## 확인 체크리스트 (수동)

| # | 확인 | 기대 |
|---|------|------|
| 1 | 상단 우측 점 | 초록 = 백엔드 연결 |
| 2 | 홈 예시 칩 클릭 | 작업실로 이동, 문장 채워짐 |
| 3 | 작업실 처리 | 결과 · 해석 칩 · 상태 배지 |
| 4 | 배경 제거 결과 | 체크무늬 위에 투명 PNG |
| 5 | 작업 상세 링크 (회원) | `/jobs/{id}` 새로고침해도 열림 |
| 6 | 작업 기록 필터 | URL `?status=failed` 유지 |
| 7 | 정답 알려주기 (회원) | 전송 후 "감사합니다 — 실패 케이스를 저장했습니다." |
| 8 | 좁은 화면(390px) | 가로 스크롤 없음, 메뉴는 아이콘만 |
| 9 | 비로그인 작업 기록·배치 | 로그인 안내 게이트, 메뉴 자물쇠 |
| 10 | 비로그인 작업실 처리 | "이 결과는 저장되지 않아요" 안내 · 결과 저장만 가능 |
| 11 | 회원가입 → 헤더 | 이름 표시, 자물쇠 사라짐, 작업 기록에 방금 작업 |
| 12 | 비밀번호 찾기 | 로컬은 `backend/logs` 의 `[DEV MAIL` 에서 코드 확인 → 재설정 → 로그인 화면 안내 |
